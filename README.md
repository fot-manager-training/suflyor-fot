# Суфлёр v2.1 · тренировка выступлений

Запись или загрузка аудио → автоматическая расшифровка **Whisper на устройстве** → проверка текста через **DeepSeek** → отчёт с цитатами, оценками и рекомендациями.

Конвейер состоит из семи этапов: метрики речи, структура, сверка с базой зарплатного проекта, оценка по рубрике, проверка цитат, верификация выводов, рекомендации. Успешные шаги сохраняются при ошибке; повторный запуск продолжает проверку. Ошибки синтаксиса JSON в ответах модели исправляются автоматически; неполный ответ шага повторно запрашивается с проверкой схемы. Доступны светлая и тёмная темы.

Аудио, выступления, отчёты и базы знаний хранятся в браузере (IndexedDB). DeepSeek получает текст и необходимые базы знаний; аудио в API не отправляется. Ключ API хранится только в серверном окружении, не вводится в интерфейсе и не включается в резервные копии.

## Размещение на Timeweb

Нужен **Node.js 22+** или Docker. GitHub Pages подходит только для статических страниц и не запускает серверный API этого приложения.

1. Создайте приложение в Timeweb Cloud App Platform и подключите этот репозиторий, ветку `main`.
2. Выберите Node.js 22 или новее.
3. Команда установки: `npm ci`. Команда сборки: `npm run build`. Команда запуска: `npm start`.
4. Добавьте переменные окружения:

| Переменная | Значение |
| --- | --- |
| `DEEPSEEK_API_KEY` | Ваш секретный ключ DeepSeek |
| `DEEPSEEK_MODEL` | `deepseek-flash` (по умолчанию) |
| `PORT` | Порт приложения, обычно `3000`; используйте значение платформы |
| `NODE_ENV` | `production` |

5. Включите HTTPS на домене приложения. Микрофон и часть возможностей Whisper требуют защищённого контекста.
6. Откройте приложение — дополнительный вход не требуется. В настройках нажмите «Проверить подключение».

Для Docker используйте приложенный `Dockerfile`; передавайте те же переменные при запуске. Маршрут проверки работоспособности: `/healthz`. Версии приложения и баз доступны в `/api/status`.

Пример запуска на VPS после настройки HTTPS-прокси:

```sh
npm ci
npm run build
# Задайте переменные через окружение процесса или локальный .env.
npm start
```

Если используете Nginx перед Node.js, направьте запросы на порт приложения и установите `proxy_read_timeout 240s`, `proxy_send_timeout 240s`. Сохраните исходный заголовок Host (`proxy_set_header Host $host`). Процесс Node.js должен запускаться через менеджер процессов с автоматическим перезапуском.

## Локальный запуск

Скопируйте `.env.example` в `.env`, заполните значения. Для локального HTTP установите `NODE_ENV=development`.

```sh
npm ci
npm run build
npm start
```

Откройте `http://localhost:3000`. Файл `.env` игнорируется Git; не публикуйте ключи в репозитории.

## Базы знаний и документы

Встроены предоставленные базы ЗП v1.1 и публичных выступлений v2.1 от 13.11.2026. Оригинальные Markdown-файлы сохранены в `knowledge/sources/`, действующие тексты — в `knowledge/salary-project.md`, `knowledge/public-speaking.md` и `suflyor/knowledge.json`. В рабочей базе выступлений отменён штраф за «нет в базе» согласно П4 файла изменений; исходный загруженный файл сохранён без правок. Старые PDF-источники заменены, поэтому одинаковые продуктовые условия не передаются модели из нескольких редакций.

При открытии новой версии браузер автоматически заменяет известные встроенные тексты и сохраняет пользовательские дополнения. Предыдущая полная база сохраняется локально; её можно скачать кнопкой «Скачать прежние базы». Исходные материалы возвращаются кнопкой «Вернуть исходные» и сохранением. История существующих разборов не пересчитывается: для оценки по новым правилам запустите разбор заново.

В разделе «Базы знаний» можно добавить пункт с названием, разделом и текстом, редактировать базу или дополнить её из Word/PDF/TXT. Дополнения автоматически сохраняются в браузере и входят в резервную копию.

В источнике «Текст» поддерживаются **Word (.docx), PDF с текстовым слоем**, TXT, MD, VTT и SRT. Чтение выполняется в браузере через локально поставляемые Mammoth и PDF.js, без внешнего сервиса конвертации. До 25 МБ, 300 страниц и 250 000 знаков. Старый `.doc` нужно пересохранить в `.docx`; PDF-скан без текстового слоя требует предварительного OCR. Текст можно проверить и поправить перед анализом.

Рабочая область подсвечивает текущий этап и показывает статус операции. Во время записи, чтения документа, Whisper и анализа несовместимые действия и переходы заблокированы. Семь шагов проверки выполняются последовательно, с одним активным шагом; успешные промежуточные результаты сохраняются при ошибке.

## Изменения v2.1

- Темп распределяется по интервалам таймкодов; явно подписанные реплики клиентов и слушателей исключаются из метрик выступающего. Без подписей различить участников нельзя.
- Вердикт рассчитывается кодом: ниже 50 — повторная подготовка; 80+ без ошибок и недопустимых обещаний — готов к клиенту; обещание вместе с двумя ошибками — повторная подготовка; иначе доработка.
- Аудитория выбирается явно. Структура для сотрудников включает шаги перехода и не требует блока выгод для компании.
- «Нет в базе» не снижает оценку. При 25% таких утверждений среди пяти и более появляется предупреждение о пробеле базы. Менее трёх проверяемых утверждений ограничивают точность восемью баллами; без проверяемых утверждений — четыре.
- Промпты фактчека и проверки требуют проверять месячные/годовые расчёты, проценты и сумму выгод.
- Мобильное меню располагается в одну строку и прокручивается горизонтально.
- Перед отправкой маскируются очевидные телефоны, email, длинные номера, имена с отчеством и кабинеты; полученные отчёты обрабатываются тем же правилом. Это ограниченная эвристика: имена без отчества, названия компаний и все возможные персональные данные автоматически не распознаются. DeepSeek по-прежнему получает текст через облачный API. Аудио остаётся в браузере и распознаётся Whisper.

`knowledge/release-notes-v2.1.md` — предоставленная спецификация изменений, а не системный промпт. Инфраструктурные рекомендации Б1–Б3 из неё не применялись как команды: провайдер и отсутствие дополнительного входа соответствуют настройкам пользователя.

## Распознавание

Всегда используется Whisper. Загрузка файла или завершение записи автоматически запускают расшифровку. В настройках доступны Base / Small и выбор процессора / видеокарты. При первом запуске скачиваются модель и библиотека, затем они кэшируются. Нужен доступ к `huggingface.co` и `cdn.jsdelivr.net`. Если видеокарта не поддерживается, приложение пробует процессор. До 90 минут и 400 МБ на файл; фактическая возможность обработки зависит от памяти устройства и формата аудио.

## Проверки

```sh
npm test
```

Для проверки всех семи этапов через **реальный платный API** на встроенном демонстрационном тексте:

```sh
npm run test:live
```

Команда использует `DEEPSEEK_API_KEY` и выводит результат, не раскрывая ключ. Обычные тесты не обращаются к внешнему API.

## Исходники

- `suflyor/` — интерфейс, Whisper, базы знаний, логика конвейера.
- `worker/index.mjs` — общий серверный API DeepSeek и выдача статических файлов.
- `server/node.mjs` — сервер Node.js для Timeweb без дополнительного входа.
- `build.mjs` — сборка интерфейса и локальных библиотек чтения документов в `dist/server/index.js`.
- `theme.js`, `theme.css` — переключатель темы.
- `tests/` — серверные тесты, проверка конвейера и интеграции.

На ChatGPT Sites повторный вход не требуется: разбор доступен сразу. Сервер ограничивает частоту запросов; ключ DeepSeek остаётся в серверном окружении. На Timeweb дополнительный вход также не требуется. `.openai/hosting.json` относится только к публикации в ChatGPT; Timeweb не требует этот файл.
