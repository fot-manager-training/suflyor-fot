# Суфлёр · тренировка выступлений

Запись или загрузка аудио → автоматическая расшифровка **Whisper на устройстве** → проверка текста через **DeepSeek** → отчёт с цитатами, оценками и рекомендациями.

Конвейер состоит из семи этапов: метрики речи, структура, сверка с базой зарплатного проекта, оценка по рубрике, проверка цитат, верификация выводов, рекомендации. Успешные шаги сохраняются при ошибке; повторный запуск продолжает проверку. Доступны светлая и тёмная темы.

Аудио, выступления, отчёты и базы знаний хранятся в браузере (IndexedDB). DeepSeek получает текст и необходимые базы знаний; аудио в API не отправляется. Ключ API хранится только в серверном окружении, не вводится в интерфейсе и не включается в резервные копии.

## Размещение на Timeweb

Нужен **Node.js 22+** или Docker. GitHub Pages подходит только для статических страниц и не запускает серверный API этого приложения.

1. Создайте приложение в Timeweb Cloud App Platform и подключите этот репозиторий, ветку `main`.
2. Выберите Node.js 22 или новее.
3. Команда установки: `npm ci`. Команда сборки: `npm run build`. Команда запуска: `npm start`.
4. Добавьте переменные окружения:

| Переменная | Значение |
| --- | --- |
| `DEEPSEEK_API_KEY` | Ваш секретный ключ DeepSeek |
| `DEEPSEEK_MODEL` | `deepseek-flash` (по умолчанию) |
| `APP_PASSWORD` | Придумайте пароль для входа в приложение |
| `APP_SESSION_SECRET` | Случайная строка от 32 символов для подписи сессий |
| `PORT` | Порт приложения, обычно `3000`; используйте значение платформы |
| `NODE_ENV` | `production` |

5. Включите HTTPS на домене приложения. Микрофон и часть возможностей Whisper требуют защищённого контекста. Приложение в production использует защищённую cookie входа.
6. Откройте приложение, нажмите «Войти», введите `APP_PASSWORD`. В настройках нажмите «Проверить подключение».

Для Docker используйте приложенный `Dockerfile`; передавайте те же переменные при запуске. Маршрут проверки работоспособности: `/healthz`.

Пример запуска на VPS после настройки HTTPS-прокси:

```sh
npm ci
npm run build
# Задайте переменные через окружение процесса или локальный .env.
npm start
```

Если используете Nginx перед Node.js, направьте запросы на порт приложения и установите `proxy_read_timeout 240s`, `proxy_send_timeout 240s`. Сохраните исходный заголовок Host (`proxy_set_header Host $host`). Процесс Node.js должен запускаться через менеджер процессов с автоматическим перезапуском.

## Локальный запуск

Скопируйте `.env.example` в `.env`, заполните значения. Для локального HTTP установите `NODE_ENV=development`.

```sh
npm ci
npm run build
npm start
```

Откройте `http://localhost:3000`. Файл `.env` игнорируется Git; не публикуйте ключи и пароли в репозитории.

## Базы знаний и документы

Встроены три предоставленных материала: база ЗП от 13.11.2026, расширенная база по публичным выступлениям и эталон «Выгода от ЗП». Тексты источников хранятся в `knowledge/`, а применяемые разделы — в `suflyor/knowledge.json`. При обновлении они дополняют существующие пользовательские базы без удаления заметок и без повторного добавления тех же документов. Инструкции из файлов сохраняются как справочный материал; они не заменяют серверные инструкции и JSON-схему конвейера.

В разделе «Базы знаний» можно добавить пункт с названием, разделом и текстом, редактировать базу или дополнить её из Word/PDF/TXT. Дополнения автоматически сохраняются в браузере и входят в резервную копию.

В источнике «Текст» поддерживаются **Word (.docx), PDF с текстовым слоем**, TXT, MD, VTT и SRT. Чтение выполняется в браузере через локально поставляемые Mammoth и PDF.js, без внешнего сервиса конвертации. До 25 МБ, 300 страниц и 250 000 знаков. Старый `.doc` нужно пересохранить в `.docx`; PDF-скан без текстового слоя требует предварительного OCR. Текст можно проверить и поправить перед анализом.

Рабочая область подсвечивает текущий этап и показывает статус операции. Во время записи, чтения документа, Whisper и анализа несовместимые действия и переходы заблокированы. Семь шагов проверки выполняются последовательно, с одним активным шагом; успешные промежуточные результаты сохраняются при ошибке.

## Распознавание

Всегда используется Whisper. Загрузка файла или завершение записи автоматически запускают расшифровку. В настройках доступны Base / Small и выбор процессора / видеокарты. При первом запуске скачиваются модель и библиотека, затем они кэшируются. Нужен доступ к `huggingface.co` и `cdn.jsdelivr.net`. Если видеокарта не поддерживается, приложение пробует процессор. До 90 минут и 400 МБ на файл; фактическая возможность обработки зависит от памяти устройства и формата аудио.

## Проверки

```sh
npm test
```

Для проверки всех семи этапов через **реальный платный API** на встроенном демонстрационном тексте:

```sh
npm run test:live
```

Команда использует `DEEPSEEK_API_KEY` и выводит результат, не раскрывая ключ. Обычные тесты не обращаются к внешнему API.

## Исходники

- `suflyor/` — интерфейс, Whisper, базы знаний, логика конвейера.
- `worker/index.mjs` — общий серверный API DeepSeek и выдача статических файлов.
- `server/node.mjs` — сервер Node.js для Timeweb с входом по паролю.
- `build.mjs` — сборка интерфейса и локальных библиотек чтения документов в `dist/server/index.js`.
- `theme.js`, `theme.css` — переключатель темы.
- `tests/` — серверные тесты, проверка конвейера и интеграции.

На ChatGPT Sites повторный вход не требуется: разбор доступен сразу. Сервер ограничивает частоту запросов; ключ DeepSeek остаётся в серверном окружении. В сборке Timeweb используется вход по паролю приложения. `.openai/hosting.json` относится только к публикации в ChatGPT; Timeweb не требует этот файл.
