# Развёртывание Суфлёра на VPS

Установщик предназначен для нового сервера **Ubuntu 22.04+ или Debian 12+ с systemd**, архитектура x86_64 или ARM64. Домен необязателен: поддерживается HTTPS на публичном IPv4. Приложение использует DeepSeek для анализа текста и Whisper в браузере для аудио.

## Перед запуском

- В панели сервера разрешите входящие TCP-порты **22, 80 и 443**. Остальные перечисленные закрытые порты не требуются. Порт 3000 будет слушать только `127.0.0.1`.
- Если используется домен, его A-запись должна указывать на сервер. Не должно быть неверной AAAA-записи.
- При наличии уже работающего Apache/Caddy на порту 80/443 установщик остановится, чтобы не нарушить его работу. Для существующего сложного веб-сервера нужна отдельная настройка.
- Подготовьте ключ DeepSeek, email для регистрации сертификата и отдельный пароль входа в Суфлёр. Пароль SSH не используется приложением.

## Установка

На своём компьютере откройте терминал и подключитесь:

```sh
ssh root@YOUR_SERVER_IP
```

Введите пароль SSH по запросу. Символы пароля в терминале не отображаются. Также можно выполнить следующие команды через веб-консоль Timeweb под root.

На сервере:

```sh
apt-get update
apt-get install -y git ca-certificates
mkdir -p /opt/suflyor
git clone https://github.com/fot-manager-training/suflyor-fot.git /opt/suflyor/source
bash /opt/suflyor/source/deploy/install-vps.sh --host YOUR_SERVER_IP
```

Вместо IP можно указать домен. Установщик спросит email, затем скрыто запросит ключ API и дважды пароль приложения. Секреты не передаются аргументами команд и не записываются в Git.

После успешного завершения откройте `https://YOUR_SERVER_IP`, нажмите «Войти» и введите выбранный пароль приложения. Вход через GPT не нужен. В настройках приложения нажмите «Проверить подключение».

Для работы микрофона открывайте именно HTTPS-адрес. Самоподписанные сертификаты не используются. Для IPv4 запрашивается сертификат Let’s Encrypt через профиль `shortlived`; Certbot 5.4+ поддерживает этот сценарий. Установщик создаёт таймер проверки продления каждый час и перезагрузку Nginx после выпуска нового сертификата.

Документация первоисточника: [IP-сертификаты в Certbot](https://letsencrypt.org/2026/03/11/shorter-certs-certbot.html).

## Что устанавливается

- Отдельный Node.js 24 из официального архива с проверкой SHA-256 в `/opt/suflyor-node`. Системный Node.js не заменяется.
- Служебный пользователь `suflyor`, который выполняет сборку и запускает приложение без root.
- Версии приложения в `/opt/suflyor/releases/`; `/opt/suflyor/current` указывает на активную версию.
- Секреты в `/etc/suflyor/environment` с правами `600`, доступные только root. Systemd передаёт их приложению.
- Сервис `suflyor.service` с автоматическим запуском после перезагрузки и перезапуском при сбое.
- Nginx: свой файл `/etc/nginx/sites-available/suflyor.conf`, HTTPS и перенаправление с HTTP.
- Certbot в отдельном Python-окружении `/opt/suflyor-certbot` и таймер `suflyor-cert-renew.timer`.

Установщик не меняет настройки SSH и не включает системный firewall. При ошибке выпуска сертификата проверьте доступность порта 80 и повторите ту же команду установки. Уже введённые ключ и пароль сохранятся. При полностью завершённой установке используйте режим обновления.

## Проверка

```sh
systemctl status suflyor --no-pager
curl --fail https://YOUR_SERVER_IP/healthz
systemctl list-timers suflyor-cert-renew.timer
```

Маршрут `/healthz` должен вернуть `{"status":"ok"}`.

Диагностика:

```sh
journalctl -u suflyor -n 80 --no-pager
journalctl -u suflyor-cert-renew -n 80 --no-pager
nginx -t
```

При ошибке SSH `Connection refused` используйте веб-консоль Timeweb: проверьте, запущен ли SSH и разрешён ли порт 22. Установщик сайта не может исправить недоступное SSH-подключение.

## Обновление и откат

```sh
cd /opt/suflyor/source
git pull --ff-only
bash deploy/install-vps.sh --update
```

Обновление собирается отдельно. Активная версия переключается только после успешной сборки; после запуска проверяется `/healthz`. Если новая версия не запускается, восстанавливается предыдущая.

Ручной откат:

```sh
bash /opt/suflyor/source/deploy/install-vps.sh --rollback
```

Старые релизы сохраняются. Ключ, пароль, сертификаты и служба продления при обновлении не сбрасываются.

## Перенос истории из ChatGPT Sites

На старом сайте откройте «Настройки → Скачать резервную копию»; при необходимости включите аудио. На новом адресе используйте «Настройки → Загрузить резервную копию». Браузер хранит историю и пользовательские дополнения отдельно для каждого адреса сайта, поэтому они не переносятся автоматически. Встроенные базы знаний уже включены в код.

## Границы проверки установщика

Проверяются синтаксис shell, формирование Nginx, закрытые права файла секретов и конфигурации службы. Реальные операции apt, systemd, выпуск сертификата и проверка доступности портов выполнятся при запуске на вашем сервере.
